## 4. Tentativa Vulkan — FALHOU (driver Adreno incompatível)

### 4.1 Configuração

O novo llama.cpp requer `vulkan/vulkan.hpp` (C++ wrapper) que não vem no NDK.

**Solução:**
- Baixar `KhronosGroup/Vulkan-Headers v1.3.275` para `app/src/main/cpp/vulkan-headers/`
- Configurar `CMakeLists.txt` com:
  - `Vulkan_INCLUDE_DIRS` apontando para os headers baixados + NDK sysroot
  - `Vulkan_glslc_EXECUTABLE` usando o `glslc` do NDK (`shader-tools/linux-x86_64/glslc`)
  - Target importado `Vulkan::Vulkan` linkando `libvulkan.so` da API 28
  - `GGML_VULKAN=ON`
- `minSdk` atualizado de 26 para 28 (Android 9+) — `vkGetPhysicalDeviceFeatures2` requer API 28

### 4.2 Build bem-sucedido

O APK compilou com Vulkan. O logcat confirmou inicialização:
```
ggml_vulkan: Found 1 Vulkan devices:
ggml_vulkan: 0 = Adreno (TM) 730 (Qualcomm Technologies Inc. Adreno Vulkan Driver) | uma: 1 | fp16: 1
register_backend: registered backend Vulkan (1 devices)
llama_model_load_from_file_impl: using device Vulkan0 (Adreno (TM) 730) - 7476 MiB free
load_tensors: layer 0..24 assigned to device Vulkan0
```

### 4.3 Crash durante carregamento

**Erro:**
```
Fatal signal 11 (SIGSEGV), code 1 (SEGV_MAPERR), fault addr 0x0
ggml_backend_alloc_ctx_tensors_from_buft+40
llama_model::load_tensors → llama_model_load_from_file → nativeLoad
```

`ggml_backend_buft_alloc_buffer` retorna `nullptr` — o driver Vulkan da Qualcomm
neste Samsung falha ao alocar o buffer de tensores. Crash ao tentar usar o ponteiro nulo.

Testado com `n_gpu_layers = 99` e `n_gpu_layers = 20` — mesmo crash em ambos.

**Conclusão:** Incompatibilidade entre o Vulkan backend do llama.cpp atualizado
e o driver Adreno 730 no Samsung (Samsung One UI com SELinux restritivo).

### 4.4 Reverter para CPU

```cmake
set(GGML_VULKAN OFF CACHE BOOL "" FORCE)
```
```cpp
mparams.n_gpu_layers = 0;  // CPU only
```

## 5. Resultado final — CPU/NEON

Inferência funcionando no S22 com NEON (armv8.4-a+dotprod+i8mm, -O3):

```json
{
  "tokens_generated": 316,
  "tokens_per_second": 7.703059,
  "total_ms": 41023.96,
  "model": "Qwen3.5-2B.Q4_K_M.gguf"
}
```

**7.7 tok/s** sustentado — excelente para CPU puro em modelo 2B reasoning.

Resposta de exemplo:
> Um NPU é um circuito de hardware especializado projetado para processar dados em
> tempo real. Ele é essencial para acelerar o treinamento e execução de redes neurais
> profundas. Muitas aplicações de IA, como reconhecimento facial e jogos inteligentes,
> dependem de NPU para funcionar de forma rápida e eficiente.

O bloco `<think>` (raciocínio interno) precisa de ~600+ tokens para o modelo completar
e entregar a resposta final após `</think>`.

## 6. Fix: modelos não apareciam na web UI

### Problema

`handleListModels()` no Android só retornava `loadedModels` (modelos registrados
explicitamente via `/api/v1/models/load`). Modelos enviados via upload iam para
`filesDir` mas nunca eram registrados → não apareciam nos dropdowns da web UI.

Além disso, os dropdowns na UI eram hardcoded.

### Fix Android — `InferenceServer.kt`

`handleListModels` agora escaneia:
- `context.filesDir` — arquivos `.gguf`, `.tflite`, `.onnx` uploadados
- `context.assets` — modelos embutidos no APK

E tenta adivinhar o tipo pelo nome do arquivo (`guessModelType()`).

### Fix Web UI — `index.html`

`selectDevice()` agora chama `populateModelSelects(key)` que:
1. Busca `/api/models?device=key`
2. Filtra por extensão (`.gguf` → LLM; `.tflite`/`.onnx` → demais)
3. Popula todos os `<select>` das abas (Detect, Classify, LLM, RemoveBG, Benchmark)
